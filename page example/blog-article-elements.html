A short opening paragraph sets up the whole post. It is set larger than the text below it and tells the reader what they will get.

The paragraph after it is regular text. It runs at a comfortable line length, with enough space between lines to read for a long time without tiring.

Real articles in this design:

  • Blog listing, version A (current)
  • Blog listing, version B (all live posts)
  • Direct vs. third-party MCP servers: the industrial edition
  • ServiceTitan - How do I connect via API Authentication?
  • Fishbowl Advanced - How do I connect via API Authentication?
  • How to connect your CMMS to your ERP without losing data on the way

Headings

A post is split into sections, and each section opens with a title like the one above.

A third level heading

A smaller title splits a long section into parts that a reader can scan.

A fourth level heading

The smallest title names a short group inside a part.

Text and links

Most of a post is plain paragraphs like this one. Keep them short, three to five sentences, so a reader sees a new paragraph before they lose their place.

Inside a paragraph you can use bold text for the thing that matters most, italics for a term or a title, a link to another page, and inline code for a value, a field name or a command. A long web address such as https://developer.example.com/portal/applications/register/new/application wraps inside the column and never pushes the page sideways.

Lists

A bullet list is for items that are equal and have no order.

  • Each item is a full phrase that makes sense on its own.
  • Items stay short, one or two lines each.
  • The list is never nested inside another list.

A numbered list is for steps that follow one another.

  1. Open the settings. Start with the first screen the reader will see.
  2. Fill in the details. A step can have a bold lead-in and a sentence after it. It can also hold a short list:
    • A bullet inside a step.
    • A second bullet inside the same step.
  3. Confirm. Each step is one action.

A checklist is for things the reader goes through before moving on.

  • One short sentence for each thing to check.
  • Items that are actions start with a verb.
  • Eight items at most, so it stays a list.

Quote

A quote pulls out a sentence worth reading twice.

A good integration is the one nobody on the floor has to think about.

Name of the speaker, role

The text continues after the quote as usual.

Callouts

A callout is a bordered block with a small label. It is used for a tip, a warning or a summary.

Tip

Keep the text to two or three lines. If it needs more, it belongs in the body.

Important

A warning names the mistake and, when there is room, how to avoid it.

Key takeaways
  • The first point the reader should keep.
  • The second point, in the same form.
  • The third point.

Code

Code goes in a block with a file name and a Copy button.

example.json
{
  "event": "record.updated",
  "id": "REC-1042",
  "status": "closed",
  "items": [ { "sku": "A-100", "qty": 2 } ]
}
request.sh
curl -X POST https://api.example.com/records \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "status": "closed" }'

Images and video

An image runs the full width of the text, with a caption underneath.

A video sits in the same place and plays with its own controls.

Questions and answers

What does a question look like?

A question is a full sentence that ends with a question mark. The answer is short and can hold a link.

How many questions can there be?

Up to eight. More than that is a page of its own.

Do they work without scripts?

Yes. Each one opens and closes on its own.
